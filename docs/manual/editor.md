# 显示与编辑器

## 为什么 `window/stretch/mode` 必须是 `disabled`

`viewport` 模式的语义是「永远渲染在固定的 1920x1080 上，然后把整张画面缩放到窗口」——
窗口一旦不是 16:9（或系统有 DPI 缩放），画面就被**拉伸**，像素变成非正方形，而且糊。

本引擎靠 **`camera.zoom`** 做像素放大（见 `PixelScale`），视口本来就该等于窗口。
设成 `disabled` 之后：

- 像素**永远是正方形**（相机 zoom 各向同性）
- 窗口变形只会「看到更多/更少的场景」，**不可能变形**
- 没有二次重采样，边缘更利落

确实想要固定分辨率 + 黑边，应该用 `canvas_items` + `aspect = "keep"`，
而不是 `viewport`（后者会把整张帧缓冲连同 UI 一起缩放）。

## 形状子节点在编辑器里是隐藏的

`PixelShape2D` 的 `position` 与刚体原点**必然重合**（形状原点就是刚体原点），
而 2D 编辑器的拾取在重叠时**优先命中子节点** —— 于是每次想拖刚体，拖到的都是形状。

所以形状子节点默认 `hide_in_editor = true`（编辑器不拾取不可见的 item）。

**视觉上零损失**：碰撞外接本来就不由它画，而是 `PixelBody2D` 画的。

| 你想做的事 | 怎么做 |
|---|---|
| 改形状参数 | 场景树里选中它，或直接在 Inspector 改数值 |
| 让形状可见（一个刚体挂多个形状、要对齐它们） | 把 `hide_in_editor` 关掉 |
| 拖整个刚体 | 直接拖 —— 命中的是刚体 |

## 编辑器里不跑物理

`@tool` 脚本在编辑器里**只构建、不推进物理**。物体不会自己掉下去，按 F5 运行才进物理。

拖动刚体时只有**位形同步**（position/rotation）—— 形状不重烘焙。
形状内容变化（改属性、改形状子节点）才触发完整重烘焙。

这条分界是编辑器流畅性的关键：重烘焙一次要 50~70 ms
（800x40 的地面光生成像素就 38 ms），而位形同步是几微秒。

## 逐像素着色（`PixelShading`，默认关闭）

`PixelShading` 给"每个材质一块纯色"加上体积感，三件事：

| | 作用 |
|---|---|
| 边沿压暗 | 和空像素相邻的面压暗，暗多少取决于开了几面 —— 方块立刻有厚度 |
| 顶面提亮 | 上方是空的面提亮 1.10 倍，假装光从上方来 |
| 色调扰动 | 每像素正负 3% 的**确定性**抖动，打破整块死平的塑料感 |

**它是烘进贴图的**，所以运行时零开销：贴图只在形状内容变化时重建
（见 `PixelShape.revision`），重建时多算几十纳秒每像素，之后每帧都是硬件贴图采样。

### ⚠️ 默认关闭

做出来之后试了一版，**色调扰动在成片的地面和碎块上读起来是噪点而不是质感** ——
画面像蒙了一层灰。像素画要的是干净利落的色块。

所以 `shading` 默认 `false`。需要体积感时再打开：

```gdscript
renderer.shading = true          # PixelRenderer
sprite.shading = true            # PixelSprite2D（@export，Inspector 里能勾）
```

### 两个实现上的坑

- **扰动必须是确定性的**。用 `randf()` 的话，贴图每次重建（破坏之后）都会让
  整片地面的噪点**整体重排** —— 画面"闪"一次，非常刺眼。这里用坐标的整数哈希。
- **查四邻域要用形状局部坐标**（`gx + aabb.position.x`），不能用贴图局部坐标 ——
  否则边沿会沿着贴图边界算，形状内部凭空出现一条暗线。

## 改完 src/ 之后要三步才对齐

```bash
python tools/build_addon.py --verify      # 构建 -> 自检 -> 移出项目树
godot --headless --path . --import        # 刷新 .godot/ 与全局类注册
# 编辑器如果开着，先关掉再重开 —— 它不会热加载新的 class_name
```

**构建产物必须待在项目树外**：addon 与 `src/` 是同一份代码的两份拷贝，脚本同名，
住在树里会让编辑器报 `Class X hides a global script class` 并**级联到编译失败**。
`.gdignore` 挡不住（只要有一个文件被加载，类就全局注册了），清 `filesystem_cache` 也没用。
