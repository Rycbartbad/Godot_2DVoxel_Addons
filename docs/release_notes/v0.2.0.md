# v0.2.0

从 v0.1.0 起共 26 个提交。主题：**从「能跑」到「能拿去做游戏」**。

## 新增

### 节点层（可用编辑器搭关卡）

- **`PixelWorld`** —— 世界容器节点，一帧推进一次物理
- **`PixelBody2D`** —— 刚体节点，可拖动、可继承、可组合
- **`PixelShape2D`** —— 形状**子节点**（对标 `CollisionShape2D`）；
  一个刚体可挂多个，每个有独立 `position` / `scale`
- **`PixelSprite2D`** —— 渲染子节点，**继承内置 `Sprite2D`**（对标 `Sprite2D`）
- **`PixelMaterial`** —— 材质 **Resource**：颜色 / 密度 / 抗压 / 抗剪在一个资源里，
  Inspector 可编辑、可存 `.tres`、可复用
- **`PixelShapePolygon2D`** —— 多边形填充形状（扫描线），像素游戏的**斜坡**直接可用

> **接口约定**：`collect_shapes()` 只认 `build_shape()` **这个方法**，不检查节点类型。
> 加一种新形状**不需要改 `PixelBody2D` 一行代码** —— `PixelShapePolygon2D` 就是证明。

### 游戏层原语（引擎提供机制，规则留给游戏）

- **逐体素辅助表** `PixelChunk.aux` / `PixelShape.get_aux/set_aux` ——
  引擎不解释内容，游戏层可以存温度、湿度、血量、材料变体
- **脏区域跟踪** `mark_dirty()` / `dirty_chunks()` / `clear_dirty()` ——
  只重算变过的分块，不用全图扫描
- **接触事件** `world.contacts`（`contact_events_enabled`）——
  每步的接触点、法向、接近速度、是否首次接触
- **体素遍历原语** `PixelShape.neighbors()` / `flood()`（4/8 邻域、可选对角线）+ DDA 射线 ——
  做红色蔓延、火焰、连通性判定这些 CA 玩法的基础件

### 破坏判据

- **接触冲量真值** `Contact.impulse` / `Contact.tangent_impulse`（从求解器取，非近似）
- **接触宽度** `Contact.contact_width` —— 数**真实重叠像素**，不是 AABB 近似
- **材质强度** `world.set_material_strength(mat, 抗压, 抗剪)`、`strength_for()`
- **法向厚度** `Query.thickness_at(body, point, normal)`
- **剪切比** `Contact.shear_ratio` —— 区分压缩与剪切加载

### 蓝图（画完先不固化）

- `PixelRenderer.sync_blueprint()` / `forget_blueprint()` / `clear_blueprints()`
- 蓝图不参与物理：宽相扫不到、不受重力、不被破坏

### 工程

- **双分支**：`main` 开发 / `stable` 稳定；`tools/promote.py` 带闸门推进
- **3 道静态闸门**（CI 会跑）
- 手册新增[节点层一章](docs/manual/nodes.md)

## 修复

### 编辑器（全是「编辑器里也在跑运行时逻辑」这一类）

- **编辑器里物体自己动** —— `PixelWorld._physics_process` 缺 `is_editor_hint` 守卫。
  ⚠️ 陷阱：**定义 `_physics_process` 本身就启用它**，`_ready` 里的守卫挡不住
- **编辑器极卡** —— `_process` 每帧 `resync()`（每帧给每个刚体重建 `ImageTexture`）
- **编辑器更卡** —— 抓手在 `_draw()` 里现算 32000 个像素
- **拖动时形状不跟随** —— `NOTIFICATION_TRANSFORM_CHANGED` **默认不发**，
  必须显式 `set_notify_transform(true)`
- **`set_world` 调用失败、编辑器里什么都不画** —— `debug_overlay.gd` 缺 `@tool`，
  编辑器里是 **placeholder instance**，脚本根本不跑

### 运行时性能

- **掉帧** —— `PixelRenderer.sync()` **每帧无条件**重建贴图
  （Ground 800×40 = 32000 像素每帧重填）。改为脏标记，只在内容真变了时重建
- **节点层卡顿** —— `PixelBody2D._draw()` 每次重绘调 `build_shape()`

### 正确性

- **同一个原点，碰撞箱在中心、精灵图在左上角** —— `CIRCLE` 从 `-radius` 铺像素
  （原点在圆心），而 `RECT`/`TEXTURE` 从 `(0,0)` 开始（原点在左上角）。
  三种来源语义不一致，`nodes_demo` 里的 `Ball` 正好中招
- **三正方体叠放抖动** —— 投机接触失效（`support()` 返回角点导致
  `normal_mass ≈ 0`）。改为切向重叠区间中心作为接触点，
  并重调 `max_depenetration_speed` 100→20、`penetration_slop` 0.5→1.0、
  `sleep_surface` 6.0→12.0
- **编辑器抓手画错** —— 静态体的框画在原点正中央。
  ⚠️ **调试可视化画错比没有可视化更糟**，它会让人去怀疑一个本来正确的引擎

### 崩溃

- **编辑器打开就闪退（`0xC0000005`）** —— 两个叠加原因：
  ① `build_addon.py` 把 `src/*.uid` 复制进 addon → 21 个重复 UID →
  Godot 构建出不一致的 UID 缓存 → 段错误；
  ② `pixel_shape.gd` 与 `destruction.gd` 相互 preload → 编辑器脚本扫描无限递归。
  已加闸门；注意**删掉 `.godot/` 还不够，必须重新 `--import`**

### 噪音

- 烘焙日志刷屏（编辑器里拖一下重建一次）→ 改为默认关闭的 `log_bake` 开关

### 内部（不影响 API，但都是会静默出错的坑）

- **批量替换误伤三个标识符** —— `to_world` / `com_world` / `center_of_mass_world`
  被 `_world`→`world` 的批量替换改成了 `toworld` 等。
  教训：批量替换要用词边界，改完必须重跑全套测试
- **对 `PWorld` id 的错误断言** —— id 是**每世界独立计数、会复用**的，
  不能断言"重建后 id 变了"。断言改成"是新对象"
- **addon 的 UID 重复污染缓存**（见上文崩溃一节）

## 已知问题

- `validation_stress` 的「窄接触应力显著大于宽接触」一项未通过。
  **机制本身已验证**（接触宽度从真实体素测出、应力=冲量/宽度成立、
  同阈值下矛破盾不破成立），但构造的撞针撞击后会转动，
  接触区不再局限尖端。是**测试场景**问题，不是引擎问题
- 图层 ④（碰撞层/掩码）、通用约束/关节、通用 `GetProperty`/`SetProperty` 未实现
- `frags:240` 回退路径在第 142 步起有 1.92e-5 偏差（疑似 warm-start 缓存键序）

## 升级注意

- `PixelWorld` 的 `palette` / `densities` 改名为 `palette_fallback` / `densities_fallback`，
  正式途径是用 `materials` 数组填 `PixelMaterial` 资源
- 形状从 `PixelBody2D` 的属性改为**子节点**。旧的内置 `source`/`rect_size` 仍可用
  （没有形状子节点时自动回退），但建议迁到 `PixelShape2D`
- 自定义形状子节点：`extends` 必须写**路径式**（`extends "res://..."`），
  不要写 `extends PixelShape2D` —— addon 里有同名脚本，全局 `class_name` 解析会失败
