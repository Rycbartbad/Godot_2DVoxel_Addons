# v0.4.1 —— CCD 不再用全局子步 + 小碎片降级

## 一句话

把「用一个**全局**机制去解一个**局部**问题」这件事改掉了：子步数不再由
「全世界最快的那一个刚体」驱动，防穿交给**逐体 CCD**。顺带把「太薄/太小的碎片
根本不当刚体」做成引擎能力（`fracture_pixels` 的新返回值 `downgraded`）。

⚠️ 本版**没有改原生 DLL**（只动 GDScript），但消费方**仍需重新部署 addon**。

⚠️ 所有新旋钮**默认关闭或保持老行为** —— 8 条逐位基准与既有闸门不变。

---

## 一、为什么「全局自适应子步」是错的（实测）

原来的 `_compute_substeps` 取「全世界最快的那个刚体」的运动，切成 N 个子步，
而**每个子步都要把整个世界重跑一遍**。于是：

```
帧时间 = 子步数（一个最快刚体决定） × 每子步代价（全世界矩形数决定）
```

两个乘数都只跟**一个**刚体有关。实测（4 像素薄墙 + 12x12 块、20000 px/s）：

| 配置 | 结果 | 峰值子步 |
| --- | --- | --- |
| 全局子步 + 逐体 CCD 软预测 0.0 | 停在 x=188.1 | **167** |
| **不做全局子步** + 软预测 1.5 | 停在 x=188.0 | **1** |
| 不做全局子步 + Rapier CCD 全关 | x=3247，**穿过去** | 1 |

**167 个子步能做到的事，1 个子步做得更好。** 使用方场景里 876 矩形规模下，
一个 2x2 的碎片以 40000 px/s 飞过 = 334 子步 = **593 ms/固定步**。

### 新增旋钮

| 旋钮 | 作用 |
| --- | --- |
| `ccd_per_body_only` | **不做全局子步**：子步数不再是「按最快刚体自适应」。默认 false |
| `ccd_fixed_substeps` | 逐体模式下用**固定**几个子步（默认 1）。⚠️ 见下面的坑 |

⚠️⚠️ **逐体模式不等于子步=1。** 子步不只是防穿 —— 它**同时**是求解器的收敛手段
（TGS / Box2D v3 的「Soft Step」）。实测把子步从 2~4 塌到 1，使用方的
`test_hand_physics` 里「grounded/held object lifted」当场变红（抬升 46.25 -> 39.88）：
**抓取变软了**。所以要拿掉的是「按最快刚体自适应」，不是子步本身。

### ⚠️⚠️ `rp_soft_ccd_prediction` 才是「逐体 CCD 有没有在工作」那个开关

它的旧说明太轻描淡写了。Rapier 的逐体 CCD 有两个旋钮，重要程度差一个数量级：

| 旋钮 | 作用 | Rapier 默认 |
| --- | --- | --- |
| `enable_ccd`（bullet 旗） | 要不要连**动态/运动学**目标一起扫 | false |
| **`soft_ccd_prediction`** | 推测 CCD 的**提前量** | **0.0 —— 等于半关** |

对静态世界那一层（自动扫掠）**不看** bullet 旗，由 `rp_ccd_substeps >= 1` 控制 ——
但**两层都吃这个提前量**。提前量是 0 时，逐体扫掠只能「正好撞上」才发现，
对一步跨几百像素的物体等于不起作用。`ccd_per_body_only` 打开时会检查这两个前提，
缺了就 `push_warning`（静默失效是最坏的失败方式）。

实测：`soft = 1.5` 会让「被推的箱子」抖到峰值 61.6（基线 0.0016 量级）——
提前量外扩太多，接触反复「提前触发」。**0.5 是量出来的甜点**，不是越大约好。

## 二、恢复与清理

- **`ccd_max_substeps` 接回**。它曾经是**死声明**：写成 16，而全引擎没有一处读它，
  真实钳制是 `ccd_substep_budget = 600`（差 37 倍）。而 `docs/manual/performance.md`
  一直写着「手动调 `ccd_max_substeps` 要小心」—— **文档说它有用，代码里它什么都不做**。
  开发日志里还留着它当年**是活的**那条记录（`_ccd_saturated = (n >= ccd_max_substeps)`），
  是 Rapier 迁移时被对象路径整块带走的。现在默认 **0 = 不限**（保持基准）。
- **抓取迟滞不再锁死**。`_substeps_held` 只涨不落，而 `grab_substep_cap` 只压 `need`、
  压不住已经涨上去的 held —— 实测 cap 算出 1 而返回值是 **77**，**768 ms/固定步**。
  这是使用方「卡死」的直接来源。现在上限**同时**作用在返回值上。
- **`_ccd_saturated` 删掉**（只被一个 diag 读过，且它驱动的位移硬钳属于已删除的对象路径）。
- **`ccd_clamp_motion` 标成墓碑**：保留声明（v0.3.2 起的 release notes 与 4 个 diag 在引用它，
  删掉会让下游报「属性不存在」），但**写明它什么都不做**，并说明为什么**不要**把它接到
  Rapier 路径上 —— 那条硬钳曾经无条件生效，把「偶发穿模」升级成「全局慢动作」
  （每子步 2 像素 = 60 fps 下 120 px/s 上限，而重力是 900 px/s²，箱子根本落不下来）。
- **`ccd_auto` 的文档重写**：旧文档描述的是「接进 `_integrate_transforms` 做精确 OBB 扫掠」，
  而那条路径（对象路径 / GDScript 扫掠）**已被删除**。旧文档里那句待办
  「应当改成按**物体自身尺寸**判定是否需要 CCD」—— **就是本版做的事**。

## 三、尺寸判据：两个量必须分开

新增 `PBody` 三件套：

| 成员 | 含义 | 用在哪 |
| --- | --- | --- |
| `thinnest_extent()` | 贪心分解出的**矩形**里最薄的那条 | **能不能穿过去**（Rapier 的 `ccd_thickness` 同义） |
| `visible_short_side()` | 所有 shape **外接盒**短边 | **看不看得见** |
| `needs_ccd(dt)` | `每步运动 > 0.5 x 最薄尺寸`（Rapier / Box2D v3 的判据） | 认出「永远满足判据」的灰尘 |

⚠️⚠️ **拿 `thinnest_extent()` 去判「这算不算灰尘」会大面积误伤**，而且症状很刺眼：
贪心分解沿**斜边**必然切出 1 像素宽的矩形，于是一块斜切的大方块 `thinnest = 1` →
整块被判成灰尘。实测：**435 像素、外接盒 29x29 的碎片**被当成灰尘 ——
玩家看到的是「碎片直接消失」。而斜切恰恰是真实破坏里最常见的形状。

## 四、小碎片降级（新返回值 `downgraded`）

`fracture_pixels` 原来只会「建刚体」或（`min_fragment_pixels`）「直接删」。
现在多一条：**太薄或太小的碎片不生成刚体**，像素原样随结果交回调用方。

| 旋钮 | 判据 | 管什么 |
| --- | --- | --- |
| `min_fragment_thickness` | 外接盒短边 < 它 | 细长条会穿墙，且穿过去没人看得出来 |
| `min_fragment_pixels_downgrade` | 像素数 < 它 | 一小撮像素不值得一个刚体 |

⚠️ **两个都要，取并集**。只按厚薄会**反直觉**（使用方报的：一条 3x200 的细长条
600 像素、看着不小，因为「薄」成灰尘；而一颗 5x5、25 像素、看着很小，因为「不薄」留下来）；
只按像素数会漏掉细长条（1x20 和 4x5 都是 20 像素，但前者会穿墙）。
**厚薄决定能不能钻过去，大小决定值不值得存在。**

配套：`PixelRenderer.place_blueprint()` / `tint_blueprint()` —— 只动 transform / modulate，
**不重建贴图**。调用方拿它们做「降级成短命灰尘」时，每帧调 `sync_blueprint`
会逐像素重填 Image + `tex.update`，而灰尘的像素内容一个字都没变。

## 六、消费方要做什么

1. 重新部署 addon（GDScript 变了，DLL 没变）。
2. 想开逐体模式：`ccd_per_body_only = true` + `ccd_fixed_substeps = 3`（量出来的），
   **并且**确认 `rp_ccd_substeps >= 1` 与 `rp_soft_ccd_prediction > 0`（0.5 起）。
3. 想开灰尘策略：`min_fragment_thickness` / `min_fragment_pixels_downgrade`
   设上之后记得处理 `fracture_pixels` 返回值里多出来的 `downgraded` ——
   **不处理就是「碎片凭空消失」**（像素没地方去）。

## 七、踩过的坑（写给下一个人）

- **拿错了度量**：用 `thinnest_extent` 判「是不是灰尘」→ 斜切大块被误伤。
- **注释和代码说的不是一件事**：灰尘渲染器第一版注释写「拿不到渲染器就每帧重试」，
  代码是「拿不到就丢掉这一批」—— 症状是「灰尘一个都看不见」。
  注释不参与执行，**它错了比没有更糟**。
- **「恒为 1」不是「不做全局子步」的正确形态**：子步同时是求解器收敛手段，
  塌到 1 会让抓取变软。要拿掉的是「自适应」，不是子步。
- **部署脚本会静默死掉**：`deploy_engine_addon.ps1` 在 `$ErrorActionPreference='Stop'` 下，
  遇到被占用的 DLL（残留的 Godot 进程）会直接终止，把 addon 留在半成品状态
  （40 个文件、没有 `.gdextension`），症状是「测试什么都不打印」。
