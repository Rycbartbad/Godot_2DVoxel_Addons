# v0.3.1

从 v0.3.0 起共 57 个提交。这一版的主线是**把 Rapier 的能力真正接出来**
（关节 / 碰撞层 / 材质），顺带把"擦除与破坏"的热路径整体压下去，
并修掉一批"看起来是手感问题、其实是数据没送到"的 bug。

## 关节：从"没有"到可放置的节点

五种关节（铰链 / 滑轨 / 焊接 / 绳 / 弹簧）走 Rapier 的冲量关节，支持限位、马达、
断裂阈值（按约束冲量判，Rapier 没有"关节断裂"这个概念）。
节点形态 `PixelJoint2D`：**节点位置就是锚点 A**，拖它就是拖支点；`body_a`/`body_b`
留空 = 接静态世界（吊桥两端挂在墙上就是这么来的）。

> ⚠️ 被关节连着的两个刚体**默认不生成接触**（`contacts_enabled = false`，
> 与 Box2D 的 `collideConnected = false` 同款默认）。关节和接触是两个求解器、目标相反：
> 体素重合的两个刚体焊在一起时，实测逐帧跳变 0.785 px/步、关节冲量 121280；关掉接触后
> 是 0.0000 / 0。只有确实需要"连在一起还互相挡"时才开。

## 碰撞层 / 掩码

`PBody.layer` / `PBody.mask` -> Rapier 的 `InteractionGroups`，查询层也一起过滤。

## 材质：密度、摩擦、恢复系数

`PixelMaterial`（Resource）里的属性现在**真的会到物理层**：

| 属性 | 效果 |
|---|---|
| `density` | 逐像素加权平均 -> Rapier 碰撞体密度 -> 质量 |
| `friction` | 摩擦系数（0 = 冰面）|
| `restitution` | 碰撞恢复系数（0 = 不弹，1 = 完全弹性）|

> ⚠️ **密度曾经完全没送到 Rapier**：GDScript 侧算出的质量（金属 7.8 -> 1996.8）和
> Rapier 默认密度 1.0（256）分叉，抓取按 `max_accel * mass` 算出来的力一步就过冲 8.4 倍，
> 症状是"拖动焊接物体不断抽搐"。修完之后同样条件 0.000 px/步。

> ⚠️ **摩擦/恢复系数是"两个碰撞体合成"的**（Rapier `CoefficientCombineRule`，默认取平均）：
> 球 0.9 + 地面 0.0 -> 接触处 0.45 -> 回弹速度 45%、高度约 20%（落 88 px 弹 19 px）。
> 想让球真的弹起来，地面也要配。实测：摩擦 0 滑 213.7 px / 0.9 滑 124.2 px。

## 抓取：语义由使用方定死

> "抓取就是向鼠标位置施加力，并补偿重力；而施加力的点就是鼠标一开始抓取的点。"
> "补偿的重力不是施加在物体的质心上，而是施加在抓取的点上，所以平衡状态下
> 质心和鼠标应该在一条竖直线上。"

三条语义：向鼠标施力（力上限 = `max_accel * 质量`，有滞后 = 重量感）、
**在抓取点上**补偿重力（`-m*g`）、力的作用点 = 最初抓取的那个点（`local_anchor`）。
实测平衡状态：单体水平偏差 +0.07 px、质心在鼠标下方 19.8 px（= 抓点到质心距离）。

> 走过并被否掉的两条路（代码里留了墓碑）：**鼠标关节**（Rapier 的马达只在锁住的轴上
> 生效，而锁住的轴就是硬约束 —— 跟踪误差恒为 0.0~0.36 px，等于强制位移；放开轴则
> 马达完全不产生力）、以及**"抓取力矩只许刹车"**（摆动是压住了，但连普通物体也一起
> 冻住）。补偿重力之后这两个补丁都不需要了。

## 编辑器体验

- 抓手（gizmo）和**形状子节点**对齐（之前用的是刚体自身内置形状，地面/墙/桥板全画成 16x16 小方块）；
- 约束（关节）的调试画法**只在 DebugOverlay 里可见**，游戏画面里不出现；
- 体素尺寸 `PixelWorld.voxel_size` 是节点属性（Inspector 可调，1~32）；
- 编辑器里画"**游戏取景框**"：可见范围与分辨率无关（`540 / voxel_size`，体素 3 时 320x180），
  不再被编辑器面板大小误导；
- 拖动 / 删除 / 改关节的**增量路径**补齐：拖刚体只同步位形（不重烘焙，50~70 ms -> 几微秒），
  拖关节只重烘焙那一个关节，删刚体节点真正把它从世界里摘掉。

## 性能（每条都要求 8 条基准逐位不变）

| 热路径 | 前 -> 后 |
|---|---|
| 擦除一笔 | 25 -> 2.84 ms |
| 边界破坏 | 16.6 -> 7.2 ms |
| 大物体切开 | 90.8 -> 66.9 ms |
| 生成碎片（质量属性）| 77.1 -> 58.6 ms |
| 分块贴图 sync | 3.04 -> 0.36 ms |

手段：GreedyRects 位网格 + **自校验**的按块分解缓存（只有被伤害碰到的块重算）、
脏矩形只 blit 本块、`_merge_pass` 去掉 O(n^2)、密度按材质记忆化。

## 稳定性

- 修"抓起别的物体，吊桥跟着抽搐"：子步数是按**全世界最快的刚体**算的，
  它一变所有刚体的步长都跟着变（实测拖动时子步数每帧在 1~6 之间跳）。
  现在抓着东西时**只涨不落** —— 不抓时保持原行为，所以基准不动。
- 修编辑器报 `Nonexistent function 'has' in base 'Nil'`：热重载 `@tool` 脚本时
  已存在的实例是旧类，新成员读出来是 Nil。
- 一次**误判的纠正**：我曾认定"桥接把 torque 参数丢了"并补了一句 `add_torque`，
  结果 `validation_dynamics` 的两条解析解断言当场变成 2 倍 —— 力矩本来就在那条路径上
  生效，那一句是重复施加。教训写进墓碑："某个量好像没生效"先拿解析解断言证伪。
