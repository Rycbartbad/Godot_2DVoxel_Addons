# v0.3.12 —— 公开方法 `sync_body_nodes()`（自己驱动步进的项目也能对齐节点层）

## 一句话

把节点层不变量的**版本号检查**抽成公开方法 `PixelWorld.sync_body_nodes() -> bool` ——
**自己驱动步进**的项目（会 `set_physics_process(false)` 的那种）终于能自己补上对齐，
不必再记"按下标取节点"的隐藏前提。

## 为什么需要它

v0.3.11 做了引擎侧根治：`PWorld` 记录刚体增删的版本号 `bodies_rev`，
`PixelWorld._physics_process` 按它自动调 `realign_body_nodes()`，消费者不用再管。

⚠️ 但那套自动对齐挂在**节点自己的每帧钩子**里 —— 而"**自己驱动步进**"的项目通常第一件事就是：

```gdscript
_main.set_physics_process(false)     # 避免同一帧推进两次
```

钩子不跑，**自动对齐也就失效了**（甲方 ink-2 正是这样接管的步进）。
所以把它抽成公开方法，让那条路上的项目自己调一次。

## 接口

```gdscript
## 按版本号检查并对齐 _body_nodes（返回是否真的对齐了）。
func PixelWorld.sync_body_nodes() -> bool
```

- 没有增删时**一次整数比较**就返回 `false`（不白付 O(n)）；
- 有增删时对齐并返回 `true`；
- `world` 还没建时返回 `false`，不报错（场景 `_ready` 之前的窗口期）。

`_physics_process` 改成调它（单一实现，不重复那段逻辑）。

自己驱动步进的项目这样用：

```gdscript
func _physics_process(delta: float) -> void:
    if _main == null or not _main.auto_step:
        return
    _main.sync_body_nodes()        # 放在渲染同步之前
    # ... 你自己的子步循环 + 渲染同步
```

## 背景（不变量本身）

`_body_nodes` 与 `world.bodies` 有一条**硬不变量**（按下标一一对应），而任何**绕过节点层**
增删刚体的路径都会破坏它：直接 `fracture_pixels`、门面 `spawn_*`、灰尘策略的 `remove_body`、
调试脚本的 `add_body`。破坏后的症状**不是报错**：

- 数组**变短** → "按下标取节点"的消费方（渲染同步循环）越界中断 → 那之后的刚体
  （通常正是新碎片）这一帧不再被 `sync`，贴图停在旧位姿 = "碎片渲染位置偏差"；
- 数组**变长** → 静默错位，`has_own_sprite` 会去问**别人的节点**。

## 附：新碎片诞生那一帧被画在错位置（物理插值）

`PixelRenderer.sync()` 新建 holder 时是"**先 `add_child` 入树、后设 `transform`**" ——
项目开着 `physics/common/physics_interpolation` 时，新节点这一帧会从**入树时的变换（原点）**
插值过来，症状就是新碎片诞生那一帧被画在错位置（最小复现：质心偏 **593 px**，
`reset_physics_interpolation()` 后 **0.4 px**）。

修法：只对**新建的那一帧** reset（每帧 reset 等于把插值关掉）。

## 闸门

`tests/validation_body_nodes_invariant.gd` 扩到 **13 项**：没有增删时返回 `false` /
有增删时返回 `true` 且真的对齐 / 再调一次返回 `false` / `world` 未建时不崩。

## 验收

- **8 条逐位基准逐位不变**；
- 全部测试非零退出 = 0；
- 本版**只改 GDScript**（`pixel_world.gd` + 手册）—— 不需要重编或重启加载 DLL。
