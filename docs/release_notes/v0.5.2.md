# v0.5.2 —— 材质：接触系数不再"取平均"，而且**逐表面**生效

## 一句话

两条改动都是"不同材质应该摸起来不一样"这件事的一部分：

1. **两个刚体接触时的系数合成规则**：从 Rapier 默认的"取平均"换成
   **摩擦 = 几何平均 √(μ₁·μ₂)、恢复 = 取大 max(e₁, e₂)**（Box2D / Bullet 的惯例）；
2. **材质系数逐表面生效**：同一个刚体上不同材质的区域**各自**带自己的摩擦/恢复
   （碰撞体按材质切开）；一整块画了多种材质的**静态地形**也不再只取第一个像素的材质。

⚠️ **本版改了原生 DLL**（`fastphys.dll` + `rapier_bridge.dll`），消费方必须重新部署 addon。

## 症状（为什么改）

### ① 取平均把一方的材质稀释掉一半

Rapier 的接触系数是**两个碰撞体合成**出来的，默认规则 `Average`：

| 场景 | 旧（取平均） | 本版 |
|---|---|---|
| 冰面摩擦 0.0 碰地面 0.5 | 接触处 **0.25** —— 冰面并不滑 | **0**（任一边为 0 就无摩擦）|
| 球恢复 0.9 碰地面 0.0 | 接触处 **0.45** —— 回弹高度只剩 20% | **0.9**（地面不配也弹满）|

旧文档把这条解释成"这不是 bug，是合成规则；想让球弹就给地面也配恢复系数"——
解释得通不等于对：那要求本身就是设计漏出来的。

### ② 整刚体只有一个系数

材质是**逐像素**存的，而 Rapier 的接触系数是**逐碰撞体**的。以前一个刚体的所有碰撞体
共用一个平均值（静态地形更是只取**第一个**非空像素的材质），于是：

- "半边冰、半边橡胶的板子"哪面朝下都一样滑；
- 石头地上铺一块冰，那一块**照样很涩**。

## 实测（`tests/validation_materials.gd`，5 -> 11 项）

| 场景 | 结果 |
|---|---|
| 摩擦 0（地面 0.5）| 滑 **647.3** px（旧 213.7 —— 取平均时接触处 0.25，不是"无摩擦"）|
| 摩擦 0.9 | 滑 124.1 px |
| 箱子 0.9 + 地面 0 | 滑 **647.3** px，与"无摩擦"一致 |
| 同上、规则改回取平均 | 滑 164.7 px（证明旋钮真的接到了 Rapier）|
| 恢复 0.9（地面 0）| 回弹 **42.3** px（旧 19.2）|
| 两边都 0.9 | 42.3 px，与"只给球配"**相同**（取大）|
| 同上、规则改回取平均 | 19.2 px |
| **两截材质方块**（上下对调），冰面朝下 | 滑 **647.3** px |
| 同上，橡胶面朝下 | 滑 **96.1** px |
| **多材质静态地形**：脚下是冰 | 滑 **500.5** px（滑进橡胶区后减速）|
| 同上，脚下是橡胶 | 滑 **96.1** px |
| 两截材质方块，弹的那面朝下 / 死的那面朝下 | 回弹 **42.7** / **0.0** px |

⚠️ 中间那两条是"逐表面"最关键的判据：两块方块的材质**完全一样**，只是上下对调 ——
它们的**整体平均系数完全相同**，所以滑行距离的差别只可能来自"接触地面的那半截是什么材质"。

## 破坏性变更（升级前务必看）

| 变更 | 旧 DLL 会怎样 |
|---|---|
| op 5 `body_set_rects` **删除** -> **op 48** `body_set_rects6`（每条记录 6 个 f32：x, y, w, h, 摩擦, 恢复）| 命令流遇到未知操作码会**吵闹地停**（"未知操作码 48"）—— 不会静默按旧格式解析错 |
| 桥接符号 `rb_body_set_rects` -> **`rb_body_set_rects6`**（签名变了，符号名跟着换）| `load_rapier` 直接失败并印出缺哪个符号 —— 不会按旧 ABI 静默调用（参数错位 = 碰撞体乱飞）|
| PixelRaster **新增** op 4 / 方法 `decompose_mat` | 老 DLL 没有这个方法 -> GDScript 回退参照实现（**慢一个量级，有警告**）|
| `PWorld.global_friction` **删除** | 没有读者了：系数现在**建碰撞体时就带**（不再"先塞临时值再整刚体重推"）|
| 默认合成规则 + 逐表面系数 | **手感会变** —— 这正是本版的目的 |

想回到旧手感：把 `PixelWorld.friction_combine_rule` 与 `PixelWorld.restitution_combine_rule`
两个下拉都设成"取平均"即可（合成规则是**世界级旋钮**）。

## 逐位基准

8 条 `dump_state` 基准**逐位不变**（基准场景全是单材质、且接触两边系数相同）。
这也是一条反向证据：这次改动的作用域恰好是"多材质 / 两边系数不同"的那一类，
单材质刚体走的还是原来那条路（`PBody.rect_friction` 为空 = 整刚体同值）。

## 代价（量出来的）

`tests/bench_mat_split.gd`（768x100 = 1248 chunk，碰撞体重建时走一次）：

| 形状 | 分解（op 2）| 按材质分解（op 4）|
|---|---|---|
| 单材质 | 0.317 ms | **0.866 ms** |
| 双材质 | 0.328 ms | 0.944 ms |
| 四材质 | 0.309 ms | 0.996 ms |
| 4x4 碎片 | 0.005 ms | 0.006 ms |

多出来的那份主要是**材质字节**（每块 64 字节）。它只发生在"碰撞体真的重建"时
（形状变了），碎片可以忽略；整屏大小的地形每笔多 ~0.55 ms。
`tests/bench_erase_boundary.gd`（768x100 贴边界破坏）本机复测：
内部小洞 2.30 / 贴边界小洞 3.31 / 沿边界拖一笔 4.12 ms/笔 —— 都在历史基准之内。

## 四种演示材质终于不一样了

此前 `materials/*.tres` **一个都没配**摩擦/恢复（全默认 0.5 / 0.0，摸起来一模一样）：

| 材质 | 密度 | 摩擦 | 恢复 | 抗压 |
|---|---|---|---|---|
| 石头 | 2.5 | **0.8** | **0.05** | 40 |
| 木头 | 0.6 | **0.6** | **0.15** | 14 |
| 铁 | 7.8 | **0.3** | **0.08** | 120 |
| 砖 | 2.0 | **0.7** | **0.02** | 20 |

冰面 = 摩擦 0.0：碰任何东西接触系数都是 0（几何平均"任一边为 0 就无摩擦"），
所以"铺一层冰"是立刻能用的玩法。
