# v0.3.6 —— 接触事件的性能（宽度惰性化 + 轻量模式 + 抓取预算标定）

> ⚠️ 这是**草稿**：版本号由人决定。要是这次发布叫别的名字，把这个文件改名即可
> （`tools/check_docs.py` 只检查"已有的 tag 有没有说明"，草稿不会挡路）。

## 一句话

接触事件里最贵的两样（**接触宽度**的逐像素扫描、`shear_ratio` 的两次厚度扫描）
不再由引擎无条件付 —— 前者改成**惰性**（读了才算），后者给了**轻量模式**开关。
实测每接触 **185 µs -> 22 µs**（8.4 倍）；要宽度不要剪切比的消费者拿 77 µs（2.4 倍）。

## 新增 / 改动

| 接口 | 说明 |
|---|---|
| `PWorld.contact_stress_enabled` | **默认 true**（老行为）。关掉 = 轻量模式：事件里点/法向/接近速度/冲量一个不少，但不做宽度扫描、不做厚度扫描，`shear_ratio` 恒 0 |
| `Contact.contact_width` | 改成**惰性属性**：不读不算，第一次读之后缓存。值与原实现逐位相同 |
| `PWorld.grab_substep_cap(total_rects)` | 抓取时子步上限的唯一真源（引擎与测试共用；以前测试自己抄了一遍公式）|
| `Query.contact_width` / `Query.solid_at` / `Query.project_span` | 从 PWorld 搬过来的静态函数（惰性 getter 在内类里跑，只能调静态函数）。算法一行没改 |
| `CCD_RECT_COST_US = 4.4` | 每矩形每子步的**实测**代价。旧注释写 1 µs —— 那是在"单个静态刚体扛 1000 个矩形"的场景量的，最便宜的一头 |

## 行为变化（要知情）

- **抓取时的子步上限按实测代价换算，比原来紧 4.4 倍**：510 矩形 -> 2 子步（旧 11）、
  1001 矩形 -> 1 子步（旧 5）。重场景里快速拖动会更容易被 `ccd_clamp_motion` 钳成慢动作 ——
  这是"绝不穿模"的既有取舍。觉得拖不动就把 `ccd_grab_substep_cost_budget_us` 调大。
- 本仓库 demo 只有 36 个矩形，碰不到这个上限；8 条基准也不抓东西 -> **逐位不变**。
- `contact_stress_enabled` 默认 true，所以老代码的物理结果**不变**（`validation_stress` 的
  矛/盾应力比值 37.0 倍不变）。

## ⚠️ 已知的既有问题（与本次改动无关，已实测确认）

`tests/validation_fusion.gd` 在"addon 住在项目树里"的情况下**会失败并卡住**：

1. addon 副本里的 `const PixelBody2D := preload(...)` 在**类型位置**
   （`node: PixelBody2D`、`c is PixelBody2D`）压不住 src/ 声明的**全局 class_name** ——
   解析到的是 src/ 那一份脚本，于是 `rebuild()` 烘焙出 **0 个刚体**（静默），
   `add_body_node` 直接抛类型错误。把 const 改名（`_PixelBody2D`）后 14 条里过 13 条 ——
   也就是这一条是 `tools/build_addon.py` 的生成规则要修。
2. 剩下那条 `add_body_node 幂等`：门面 spawn 出的刚体让
   `_body_nodes` 与 `world.bodies` 的下标对应错位（`sync_world_bodies()` 才恢复），
   而 `add_body_node` 的幂等分支按下标取 body -> **返回了别的刚体**。这是节点层的既有问题
   （`0643ee7` 交付3 动过这段）。

两条都**不是**本次改动引入的：把本次的 `src/physics/*.gd` 改动 stash 掉、重新构建 addon
之后，症状逐字相同（同样的两条 FAIL + 同样的 SCRIPT ERROR + 同样卡住不退出）。
