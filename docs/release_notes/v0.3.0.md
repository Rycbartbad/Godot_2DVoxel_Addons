# v0.3.0

从 v0.2.2 起共 24 个提交。**这一版把物理内核整个换掉了** ——
手写的碰撞/宽相/求解器全部删除，物理交给 [Rapier](https://github.com/dimforge/rapier)（`rapier2d 0.36`）。

## 为什么换

不是因为性能。手写内核在**鲁棒性**上过不去，两个问题反复出现且越修越复杂：

| | 手写内核 | Rapier |
|---|---|---|
| 幽灵碰撞（静止体自旋偏差） | 16.16 / 14.91 px，并且打转 | **0.0044 / 0.0047 px** |
| 120 个碎块入睡 | **0 / 120** | 全部入睡 |
| 240 个碎片每步 | 1.79 ms | 0.067 ms |

> 幽灵碰撞的根因值得记下来：**Rapier 修好它，主要不是因为有伪法向，
> 而是因为它默认不用「推测接触边际」**。把这个边际调大，等于把引擎原来的
> `max_speculative_margin` 装回去，假接触原样回来。
> 参数是 `prediction_distance`，本项目的默认值 0.02 必须保持。

## 架构

物理通过一层薄桥接进入引擎：

```
GDScript (PWorld / PBody)
    -> RapierPhys（GDExtension 类，只暴露一个方法 cmd(in, out_template)）
        -> fastphys.dll（约 500 行的加载器 + 命令流编解码）
            -> rapier_bridge.dll（纯 C ABI 的 Rust cdylib）
```

命令流是一条 `PackedByteArray`，24 个操作码（建体/设矩形/设位形/步进/读回/接触/力/CCD/世界参数）。
一次 `cmd()` 调用完成一整帧的全部推拉，避免逐刚体跨界调用的开销。

**两个 DLL 必须一起重建** —— 只重建一个会让 `load_rapier()` 失败，
症状是「所有刚体停在原点」，且没有任何报错。现在未知操作码会直接中止并打印。

## 节点层与门面层融合

`PixelWorld`（场景节点）和 `PixelPhysics`（代码门面）原本是**两个并列前端**，
各自 `PWorld.new()` 一个世界 —— 编辑器里摆的关卡和代码里 spawn 的刚体
活在两个世界里：互相看不见、也不碰撞。

现在共用一个世界：

- `PixelPhysics.attach_to(world_node)` 接管节点的世界与渲染器，并关掉自己的
  `auto_step` / `auto_render`（两边都推进 = 物理一帧走两次，症状是「重力怎么突然变大了」）
- `PixelWorld.add_body_node()` / `remove_body_node()` / `bake_node()`
  —— **增量烘焙**，运行时加刚体不再需要 `rebuild()`（那会造一个全新的世界，
  破坏掉的像素、正在飞的碎块、抓取全部丢失）

> 融合时撞上的真问题：addon 会**自带一份**引擎脚本的副本，开发仓库里
> `src/` 与它同时存在，两份是**不同的 GDScript 资源**，Godot 按脚本身份做类型检查 ——
> 跨副本赋值报 `Trying to assign value of type 'pworld.gd' to a variable of type 'pworld.gd'`
> （两边名字一模一样，报错却看不出所以然）。门面的世界引用改成鸭子类型后通过。

## 性能

**融合后的节点路径已经低于纯门面的开销**（纯门面每帧连静态体也同步）：

| 刚体 | 物理 | 节点 | 纯门面 | 节点省 |
|---|---|---|---|---|
| 5 | 24 µs | 65 µs | 4328 µs | 98.5% |
| 241 | 1044 | 4846 | 10107 | 52.0% |
| 601 | 2889 | 19924 | 28751 | 30.7% |

**擦除地面**（这一版修了两处，第三处待做）：

- `PixelShape.local_aabb()` 加 revision 键缓存 —— 它遍历所有 chunk，
  768x100 是 1248 个，实测 4.48 ms/次，而渲染器的脏检查**每次 sync 都要调**。
  未变化时的 sync：**4.48 ms -> 0.00 ms**
- 原生破坏路径报告受影响的块范围（`mark_dirty_range`）—— 以前只能 `touch()`，
  那是「整块都脏」的信号。现在每笔擦除只标 **30/1248 = 2.4%** 的块
- 渲染层分块增量重绘：CPU 光栅化只画脏块（44 -> 31 ms）。
  **剩下的 ~30 ms 是 `tex.update()` 仍在上传整张贴图** —— 下一步是每块独立贴图

## 新增工具

- `tools/doctor.py` —— 体检并修复三类**静默失效**状态：
  addon 住进项目树（UID 冲突 -> 测试整批加载失败、编辑器打不开）、
  `.godot/extension_list.cfg` 丢失（扩展不加载 -> 物理完全不动）、
  `.godot/uid_cache.bin` 被污染
- `tools/build_native.py` —— 构建两个 DLL。**先检查编辑器是否开着**，
  因为运行中的 Godot 会锁住 DLL，重建会静默失败，症状是「物理完全不动」

> 这三类故障都不在代码里留痕迹，报错也都不指向真因 —— 所以做成了工具。
