## 内容

- **C++ 求解器移植**：GDScript 求解器移植到 `gdext/`，与 GDScript 路径**逐位一致**
  （编译要求 `-ffp-contract=off`，否则浮点乘加会被融合成 FMA，两条路径立刻分叉）
- **窄相**：SAT + 贪心矩形分解，原生与回退路径给出**完全相同的流形**
- **引擎包抽取**：`src/` 是唯一真源，`tools/build_addon.py` 生成可迁移的 addon
  （`addons/pixel_destruction/` 是**构建产物**，不进仓库）
- **破坏系统**：像素级破坏、连通分量分裂、光栅化爆炸
- **查询**：体素 DDA 射线、最近点、扫掠
- **工程化 API 文档**：用 Godot 官方 `--doctool --gdscript-docs` 导出结构，
  再由 `tools/gen_api_docs.py` 拼成 Markdown（结构取自 XML，排版取自源码注释）
- **开发者手册**：按任务组织的四份文档
- **许可**：MIT

## 主要类

| 类 | 作用 |
|---|---|
| `PWorld` | 物理世界：宽相 / 窄相 / 求解 / 睡眠，一帧一步 |
| `PBody` | 刚体：位置、速度、质量属性、碰撞矩形 |
| `PixelShape` | 像素形状（分块位图），破坏与查询都作用于它 |
| `Solver` / `Collide` | 求解器与窄相，两条路径逐位一致 |
| `Destruction` | 破坏：雕刻、分裂成连通分量、爆炸 |
| `Query` | 体素 DDA 射线、最近点、扫掠 |
| `PixelPhysics` | 门面（手写模板，在 `addon_src/`） |

## 精度纪律（从一开始就定下）

- Godot 的 `Vector2`/`Rect2` 是 **float32**，GDScript 标量是 **float64**
- `Vector2 * real_t` 会先把标量**截断成 float32**
- **绝不从 C++ 侧 resize PackedByteArray**（调用方准备缓冲，C++ 写入；
  截断时返回恰好 cap 个条目，GDScript 检测到后翻倍重试）

这几条后来每一次出"两条路径不一致"的问题，根因都在这里。
