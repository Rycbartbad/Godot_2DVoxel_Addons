# v0.5.3 —— 旋钮收口：`PhysicsConfig`（单一真源 + 一处下发）

## 一句话

物理旋钮以前最多有**三个家**：`PWorld` 的字段、`PixelWorld` 的 `@export`、门面
`configure(opts)` 的键表 —— 三份默认值各自演化，"现值是多少"要读三个文件才能回答。
这一版把它们收进一个 Resource：**`PhysicsConfig`（57 个旋钮）**，
**字段名就是 `PWorld` 的字段名**，一处下发，名字对不上就**吵闹**。

⚠️ **本版没有改原生 DLL，也没有改任何物理行为** —— `dump_state` 8 条逐位基准**逐位不变**。
消费方升级只需要替换脚本（原生库沿用 v0.5.2 的那两个）。

## 用法

```gdscript
# 代码路径
var cfg: PhysicsConfig = load("res://my_physics.tres")
world.apply_config(cfg)          # 等价于 cfg.apply(world)

# 节点路径：把 .tres 拖到 PixelWorld.physics 上（rebuild / push 时下发）
```

- `apply(world)` 逐字段下发，返回**没找到的字段名**并 `push_error` ——
  `Object.set()` 对不存在的属性是**静默失败**，而"旋钮静默失效"正是这一版要消灭的东西
  （踩过：改了 `@export`，`world` 那边还是 0）。
- `capture(world)` / `diff(world)` 与它对称：探针里做"现值快照 / 逐项对照"。
- 字段清单 `knob_names()` 从脚本属性表里取 —— **不手写第二份列表**（新增一个旋钮只要加一个 `@export`）。

## 老场景不会炸（这是硬约束）

- **没设** `PixelWorld.physics` 时一切照旧：节点上那些 `@export` 照常播到 world（老关卡不动）。
- **设了**它，**配置说了算** —— 节点上的 `@export` 不再参与下发。
  两处都设 = 谁最后写谁赢（config 在 rebuild/push 时下发，`@export` 的 setter 是改了立刻播），
  所以**关卡里别设这些**，要改就改 config。
- 57 个字段的默认值与 `PWorld` **逐位相同** —— 这条由闸门第 ① 项保证，不是人工核对。

## 闸门（`tests/validation_physics_config.gd`，14 项）

判据全部是"下发之后世界变成什么样"，不是"字段存在"：

| 判据 | 抓什么 |
|---|---|
| 全新配置 -> 全新世界，**每个字段逐位不变** | 默认值搬错了（手感静默改变）|
| 每个字段设成探针值 -> 世界逐个收到 | 名字写错了（`set()` 静默失败）|
| `capture -> apply` 往返一致 | "现值快照"真的可用 |
| 假世界（只有一个字段）-> 缺失名单列全 + 报错 | 吵闹，不是静默跳过 |
| KNOBS 映射到的 13 个世界字段都在 config 里 | 漏一个 = 改用 config 的场景**静默丢掉**那个旋钮 |
| 节点 `@export` 默认值 vs config 默认值（13 项） | 消重：同一个旋钮两个默认值 |
| 设了 config 时配置赢 / 没设时老路照旧 | 收口 + 老场景不炸，两条都要 |

## 迁移建议

- **老项目**：什么都不用做。
- **想收口**：建一份 `.tres`，把散落在游戏代码里的 `world.set(...)`、门面 `opts`、
  关卡 `.tscn` 里的旋钮行搬进去，然后 `world.apply_config(cfg)`。
- ⚠️ **别在游戏工程里自己再建一个 `physics_config.gd`**：`class_name PhysicsConfig` 是**全局**的，
  同名会报 `Class "PhysicsConfig" hides a global script class` 并级联编译失败。
- ⚠️ **从 v0.5.1 或更早升上来的**：先读 [v0.5.2](v0.5.2.md) 的破坏性变更
  （op 5 -> 48、桥接符号改名、材质逐表面 + 合成规则从"取平均"改成"摩擦几何平均/恢复取大"）——
  那一版**必须重新部署原生 DLL**，本版不需要。
