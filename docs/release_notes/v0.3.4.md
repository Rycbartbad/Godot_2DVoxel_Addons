## 切向（摩擦）冲量：接触点的冲量是"法向 + 切向"之和

用户指出："冲量不应该是沿法向的吧" —— **对，之前的表述不准确**。

接触点的冲量有两个分量：

- **法向**（单边约束，>= 0）—— 这是原先导出的 `ContactData.impulse`（Rapier 文档：along the contact normal）；
- **切向**（**摩擦**，被 mu * 法向裁剪）—— 之前**没导出**。

所以物理上它是**向量**，只有摩擦为零时才沿法向。现在每点 9 个 f64（stride 64 -> 72）：

    nx, ny, px, py, dist, impulse(法向), tangent_impulse(切向), fid1, fid2

完整向量：`j = normal * impulse + Vector2(-normal.y, normal.x) * tangent_impulse`
（2D 的切空间是 1 维，所以切向是个标量）。

**实测**（盒子以 200 px/s 在静态地面上滑动）：

    采样1 速度 159.62：法向 1933.1852 切向 -966.5926  -> |切向|/|法向| = 0.5000
    采样2 速度 137.47：法向 2992.2041 切向 -1496.1021 -> 0.5000
    采样3 速度 106.45：法向 3635.3049 切向 -1817.6525 -> 0.5000

⚠️ 比值**恰好 0.5000** = 材料的摩擦系数 —— 即库仑约束 `|切向| <= mu*|法向|` **取到边界**，
说明盒子在**滑动**（动摩擦饱和）。这是**正确性证据**，不只是"有个非零数"；符号为负 = 摩擦与滑动反向。

⚠️ 两点如实说明：多点里只有**受载**的那个点有值，另一个是 0（盒子轻微倾斜、只有一条边接触），
这个 0 是真的；`contact_entries` 的份额**仍按法向**冲量算（撞击的"多猛"是法向那部分，
摩擦不是撞击），切向只是把数据摆出来给调用方。

## 门面接触接口

问："在 Godot 中这些数据会怎么给出" —— 查下来发现**门面 `PixelPhysics` 里一条接触接口都没有**，
接触数据此前只能从 `.world` 逃生口拿（而门面自己的注释写着"优先用门面的方法"）。

补上四个方法：

    contact_pair_count() -> int
    contact_points(idx) -> [{normal, position, dist, impulse, tangent_impulse, fid1, fid2}, ...]
    contact_info(idx) -> {points, total_impulse, id_a, id_b}
    contact_entries(idx, base_radius, min_share) -> 共享预算的损伤入口

⚠️ 注释写明两条约定：**不需要开事件**（查询直接读求解器，每帧都能查；只有 `Contact` 事件
要 `contact_events_enabled`）；**在步进之后查**（接触是 step 的产物）。
⚠️ 项目一贯用**轮询**而不是 signal（`src/nodes/*.gd` 里一个 signal 都没有），所以给的是方法。

实测（`add_ground` + `spawn_circle` 砸下去）：接触对 1、点数 2、总冲量 1026.6666，
各点 513.3624 / 513.3043，之和 / 总冲量 = **1.0000**，入口 share=0.5 radius=5.6570。

⚠️ 附带查清的一件事：开发仓库里 `addons/pixel_destruction/.gdignore` **存在**，
所以 `class_name PixelPhysics` 在**开发仓库**里注册不了（headless 下要 preload）。
这**不是缺陷**：`.gdignore` 由 `build_addon.py` 生成（避免与 `src/` 的类名冲突），
而 `package_addon.py` 打包时会**剔除它** —— 发布出去的 addon 里 `class_name` 正常可用。

## 实测：Godot 自带物理的接触冲量返回 (0,0)

我曾在对照表里把 `PhysicsDirectBodyState2D.get_contact_impulse(idx) -> Vector2` 写成"该点的冲量"。
实测（本地 4.7.2 stable，带摩擦滑动的盒子，`contact_monitor` 与 `max_contacts_reported` 都开，
接触点确有 2 个、摩擦确在起作用）：

    点0 法向=(0.0,-1.0) 冲量=(0.0,0.0) | |法向分量|=0.000 |切向分量|=0.000

**两种时机都是 (0,0)**：`_integrate_forces(state)` 里读（那个回调跑在**求解之前**）、
以及 `await physics_frame` 之后用 `PhysicsServer2D.body_get_direct_state()` 读。

=> "Godot 自带物理能给每点冲量"**在这次实测里不成立**。方法确实存在（类参考里有签名），
但没给出非零数据。真因**未查**（候选：4.x 的 2D 物理重写后该字段没填 / 监视器那份副本不带冲量 /
只在硬撞击时才填 —— **都未验证**）。⚠️ 结论边界：只试了**滑动接触**，没试**硬撞击**。
