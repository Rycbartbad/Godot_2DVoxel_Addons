# v0.2.2

## 新增

### 发布前同步文档，做成闸门

「每次发布前先同步文档」这条规则，**光写进文档是挡不住的** ——
本仓库已经证明过一次（AGENTS.md 写了「开发只在 main」，助手照样自己推进）。

所以做成机制：`tools/check_docs.py`，由 `promote.py` 在跑测试**之前**调用，
不过就**拒绝推进 stable**。

它查两件事：

- 每个 `class_name` 都要在文档里出现过（代码里加了类、文档一字未提 = 最常见的漂移）
- 每个 tag 都要有发布说明，且不能是空壳（少于 400 字符）

**它上线就抓出两个真缺口**：`PixelShading` 文档一字未提、`v0.1.0` 没有发布说明。
两个都补了。

> 闸门自己也可能出错。第一版查的是「说明里必须提到至少一个类名」，**误报了** ——
> `v0.1.0` 明明列了 `PWorld`/`PBody`/`PixelShape` 却被判「没提到」。
> **会误报的闸门比没有闸门更糟**：它会训练人绕过它。
> 换成可度量的判据（长度）后用探针反证过 —— 把说明改成「见 changelog。」确实会被抓到。

## 变更

### demo 场景：相机与 UI 改用 Godot 原生场景节点

`nodes_demo.gd` 的文档写着「本场景全部由场景节点摆出来……没有一行生成代码」，
而它自己第 16 行 `Camera2D.new()`、第 34 行 `Label.new()` —— **文档和代码互相打脸**，
而且相机和 UI 在编辑器里看不到、调不了。

| 之前 | 现在 |
|---|---|
| `Camera2D.new()` 代码建 | **`Camera2D` 场景节点**，position 可在编辑器里拖 |
| `Label.new()` 代码建 | **`CanvasLayer` → `Label` 场景节点** |
| `nodes_demo.gd` 40 行 | **20 行** |

代码里只剩 `camera.zoom` —— 它按**视口高度**算，场景文件里写不成静态值。
