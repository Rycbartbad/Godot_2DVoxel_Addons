# v0.3.9 —— 渲染栅格化原生化（27x）+ 两个泄漏/卡死根因

## 一句话

逐像素填图搬进原生（新类 `PixelRaster`）：**768x100 填图 50.3 -> 2.1 ms（27x）**，
AABB 变化不再全量重建贴图；修掉 `cull_outside` 在 Rapier 侧的**刚体泄漏**；
新增**灰尘策略 + 角速度上限**并把旋钮暴露到节点层/门面；删掉 demo 里那条会把游戏卡死的撞击破坏规则。

## 一、渲染：逐像素填图进原生（新类 `PixelRaster`）

| 场景 | v0.3.8 | v0.3.9 |
|---|---|---|
| 逐像素填图 768x100 | 50.3 ms | **2.1 ms**（0.654 -> 0.028 us/px）|
| 切割一帧（768x100 一刀两半）| 77 ms | **26.5 ms** |
| 右边缘切一刀后的贴图重建 | 24/24 块 | **2/24 块** |

- 新原生类 `PixelRaster`（**自己的命令流**，op 1 `fill_region`）—— 纯 CPU 栅格化，与 Rapier 无关，
  所以它不占用 op 42（那是 `body_set_solver_iterations`）；
- `PixelRenderer` 走原生路径，GDScript 实现留作**参照实现**（`_build_region_image_gd`），
  `tests/validation_raster_native.gd` 拿它逐位对照（378 项 / 374 处逐位比较）；
- AABB 变化（切割、摘除）不再"全量重建"：脏块信息现在**照常收**，只有"内容变了但脏信息丢了"
  才保守重建；
- ⚠️ 剩下的 22.7 ms 里 **86% 是 `fracture`**（不是渲染）—— 下一步的可行性测量见 development_log「表 ⑥」。

## 二、修掉一个真泄漏：`cull_outside` 在 Rapier 侧删不干净

`cull_outside` 绕过 `remove_body()` 直接从数组里删 -> **GDScript 侧 1 个刚体、Rapier 侧 501 个**。
实测成本 ~0.34 us/僵尸/步（8000 个僵尸 = 2.695 ms/步），关节同样漏。现在两边一起删（含关节）。

顺带修掉第二个 bug：剔除绕过节点层 -> `_body_nodes` 下标错位 -> 每帧拿**别人的节点**判断渲染归属
-> 对**该画的刚体**调 `forget()`。新增 `PixelWorld.realign_body_nodes()`。

## 三、灰尘策略 + 角速度上限（新旋钮，默认不动既有场景）

子步数取的是"**全世界最快**"的那个刚体，所以**一个** 2x2 碎片（质量 4）就能拖慢全世界：

| 2x2 碎片的速度 | 子步 | 那一帧 |
|---|---|---|
| 0 | 3 | 3.4 ms |
| 5000 px/s | 42 | 42.9 ms |
| 40000 px/s | **334** | **345.8 ms** |

| 新旋钮 | 默认 | 作用 |
|---|---|---|
| `max_angular_velocity` | 1000 rad/s | 角速度上限。**Rapier 2D 0.36 没有这个旋钮**（翻过 crate 源码），引擎在回读处自己钳 |
| `ccd_ignore_mass` | 0（关）| 轻碎片**豁免子步估计**（代价：它会穿墙）|
| `debris_max_mass` + `debris_min_speed` | 0（关）| 又轻又快 -> 直接删（**破坏体素守恒**）|

三处都能调：`PixelWorld` 的 Inspector（"物理"/"破坏"两个组）、代码（改完调 `push_physics_settings()`，
**别用 `rebuild()`** —— 那会重建世界、丢掉破坏状态）、门面 `px.configure({...})`（没给就不动）。

判据用的是 `_motion_of`（线速度 **+ |角速度| x 外接半径**），与子步估计**同一个度量** ——
只看线速度会漏掉角速度那个**质量放大**通道（`Δω = J·r/I`，而 `I ∝ m`）。

## 四、demo：删掉撞击破坏（"快速多次擦除后卡死"的根因）

判据用了 `contact_info` 的**冲量**，而冲量里混着**静置重量 m*g*dt**（实测：静置 8000 / 撞击 1.04e6）——
两者只差一个数量级，**任何固定阈值都分不开**；重物光是"压在地上"就每 0.5 秒炸一次，
每次炸出的碎片又形成**新的接触对**（冷却按刚体对，新碎片全是新对）-> 自我维持的破坏循环，
碎片指数增长 -> 卡死。整条删除，机理与实测数字见 development_log。

> 要做这个玩法，用**与质量无关**的量：接触事件里的 `Contact.approach`（接近速度）+ `is_new`，
> 见 `docs/manual/cookbook.md` 第 6 节。

## 五、同期带来的其它改动

- **锚定断裂**与**局部求解控制**：`PJoint.set_solver_softness(freq, damping)`、
  `PWorld.rp_joint_solver_iterations` / `rp_warmstart_joints` / `rp_warmstart_coefficient`、
  `PBody.additional_solver_iterations`（12 节焊链静定后：1 次迭代 -> 误差 17.38 px，
  默认 4 次 -> 0.75 px，8 次 -> 0.65 px）；
- **门面路径的渲染归属**：判据收敛成一个 `PixelWorld.uses_internal_render(node)`，
  四条同步路径共用；新增 `PixelBody2D.internal_render`（不可见的臂/手**不再需要透明精灵占位**）。
