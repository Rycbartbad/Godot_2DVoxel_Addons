# v0.3.10 —— 破坏路径三档提速（每笔破坏 3.4 -> 1.5 ms）+ 灰尘策略语义修正

## 一句话

`fracture_pixels` 的三笔固定开销各降一档：**质量属性逐块复用**、**统一内部/外围**、
**原生矩形分解（顺带把 AABB 一起算）** —— 800x40 的形状每笔破坏 **3.40 -> 1.49 ms**。
另修掉 v0.3.9 的两个坑：`debris_min_speed = 0` 现在表示"不限速度"、节点层旋钮**改了就生效**；
并加了公开钩子 `pre_step(dt)`（自己驱动子步的项目不再漏掉灰尘清理）。

## 一、破坏性能：按形状大小收费的三笔账

起因：ink-2 里"玩家跳在**很小**的碎片上"掉到个位帧率。量下来根因不是碎片，而是
`fracture_pixels` **按形状大小收费、与删多少像素无关**（800x40 = 32000 像素，删 1 个像素也是这个价）：

| 形状 | 像素 | 优化前 | 优化后 |
|---|---|---|---|
| 800x40 | 32000 | **5.8 ms** | **1.49 ms** |
| 200x200 | 40000 | 5.8 ms | ~1.6 ms |

三笔账分别处理：

| 那笔钱 | 优化前 | 优化后 | 做法 |
|---|---|---|---|
| `MassProps`（逐块扫质量属性）| 2.95 ms | **0.81 ms** | 逐块几何缓存：只重算脏块，其余复用 |
| `GreedyRects.decompose` | 2.03 ms | **0.11 ms** | **原生化**（op 2），并把 **AABB 一起算** |
| 其余（touch / refresh_com / update_aabb）| 0.02 ms | 0.02 ms | 本来就不是瓶颈 |

⚠️ **最重要的一条发现：那 2.0 ms 里 1.8 ms 不是贪心**。`decompose()` 第一句是
`local_aabb()`，它遍历全部 chunk 逐行取最低/最高置位 = **1.83 ms**；真正的分块贪心只有
**0.20 ms**。**只搬贪心等于白做** —— 1.8 ms 只会挪到下一个 `local_aabb()` 的调用方
（`update_aabb` / 渲染器脏检查）。所以原生 op 2 把 **AABB 一起算**（出参）并写回形状的
AABB 缓存。

`decompose` 原生 vs GDScript 参照（800x40，各 20 次取最好值）：

| | GDScript 参照 | 原生 |
|---|---|---|
| 热（AABB 缓存新鲜）| 0.205 ms | **0.107 ms** |
| 每笔破坏（AABB 被作废）| **2.031 ms** | **0.111 ms** |
| 冷（块缓存全空）| 2.950 ms | 0.286 ms |

- 新原生 op：`PixelRaster` **op 2 `decompose`**（与 op 1 `fill_region` 同一个类，不与 Rapier 冲突）；
- GDScript 实现**原样保留**为 `decompose_gd()` 当参照实现；
- ⚠️ 闸门 `tests/validation_greedy_native.gd`（**435 项 / 87 组形状 / 57180 个矩形 x 4 分量**）
  逐条比 4 个分量**和下标**（顺序也是判据 —— 它会进入 Rapier 的碰撞体顺序），
  并带"真的走了原生"的计数（否则退回 GDScript 会让闸门变成同义反复）；
- ⚠️ 闸门当场抓到一个真 bug：**空 AABB**（有 chunk 但一个像素都没有）原样写回了哨兵 `1 << 30`，
  而它会被写进形状的 AABB 缓存 —— 症状正是"形状与碰撞体**静默**错位"。

⚠️ `MassProps` 缓存的失效判据是**调用方声明**：传了 `changed_keys` 才复用，没传就清空全量重算；
而且**断出碎片时不传** —— `split(adopt=true)` 会把 `PixelChunk` **对象**搬到新 shape 上，
块键不变但内容已不是缓存里记的那份（闸门"甜甜圈：质量属性仍然逐位正确"当场抓到）。

## 二、灰尘策略：两个语义坑修掉

- **`debris_min_speed = 0` 现在表示"不限速度"**（只按质量清，**躺着的也清**）。
  v0.3.9 里 `0` 是"全关"，而任何正阈值都拦得住躺在地上的碎块 ——
  **静止的碎片 motion 恒为 0**（实测 1 / 0.5 / 0.1 / 0.01 / 0.001 全都没清）。
  现在两种需求都能表达：`> 0` = 只清"正在飞的"（挡子步尖峰）；`= 0` = 扫地。
- **质量 = 像素数 x 材质密度**，不是像素数：4x4 的碎片在密度 2.5 下是 **质量 40**、
  密度 7.8 下是 **124.8**。"设了 20 却一个都没清"多半就是这个。

## 三、节点层：旋钮改了就生效（不再需要手动 push）

v0.3.9 里 `PixelWorld` 的物理旋钮**只在 `rebuild()` 里播一次** —— 运行时改 `@export` 是
**静默不生效**（Inspector 路径本来就通，代码路径不通，同一个旋钮两条路行为不一样）。
现在 11 个旋钮的 setter 都**立刻播到 world**（`_push_knob` 是唯一的映射表）；
`push_physics_settings()` 只在 `rebuild()` 之后或你自己换了 world 之后才需要。

## 四、新公开钩子：`pre_step(dt) -> int`

`cull_fast_debris()` 原本只挂在 `step()` 里，而"**自己驱动子步**"是合法用法
（要逐子步结算接触伤害就必须自己写那个循环）—— 那些项目里灰尘清理**一次都没跑过**，
阈值设到 1000 也没用，而且**不报任何错**。现在前段抽成公开方法：

```gdscript
var n := world.pre_step(dt)      # 清接触事件 + 刷新质心 + 灰尘清理 + 子步估计
for i in n:
    world._substep_rapier(dt / float(n))
```

## 五、防穿有两层（实测）+ 一个静默失效修复

| ccd_enabled（本引擎子步）| rp_ccd_substeps（Rapier CCD）| 30000 px/s 撞 4px 薄墙 |
|---|---|---|
| true | 1（默认）| 挡住 |
| true | 0 | 穿过去了 |
| **false** | **1（默认）** | **挡住** |

**`ccd_enabled = false` 不会顺带关掉 Rapier 的 CCD**（两个独立的 op）。所以"`ccd_ignore_mass`
豁免会穿墙"这个代价只在**第二层也关掉**时才成立 —— 默认配置下豁免几乎是免费的。

⚠️ 顺带修掉：`rp_ccd_substeps = 0`（合法设置）**在第一步之前设会被守卫吃掉**
（镜像初值是 0，而"值没变就不推"）—— 用户以为关了、Rapier 那边还是默认 1，且不报任何错。
镜像初值改成 `-1`。教训：**"值变了才推"的镜像初值不能等于任何一个有意义的取值**。

## 验收

- **8 条逐位基准逐位不变**；
- 全部测试非零退出 = 0，含新增 `validation_greedy_native`（435）/ `validation_mass_cache`（15）；
- ⚠️ 这一版重编了 `fastphys.dll`（新增 op 2）：**编辑器要重启**才会加载新 DLL，
  否则矩形分解会退回 GDScript 路径（每笔破坏慢 ~1.9 ms）。
