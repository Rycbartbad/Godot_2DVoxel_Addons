# v0.2.1

从 v0.2.0 起共 15 个提交。主题是**把"看起来修好了"变成"真的修好了"**。

> v0.2.0 里有几个提交宣称修好了掉帧、拖动跟随、冲量回填 ——
> 后来由一次独立代码审查发现**它们从来没有生效**，只是不报错。
> 这个版本把它们真正修掉了，并且给每一条都补了**判决性证据**。

## 修复（严重）

### 编辑器卡死（进程涨到 2.2 GB，Responding=False）

**现象**：拖动几下编辑器就卡死。

**根因**：拖动和「形状变了」走同一条路（`on_child_moved → rebuild`），
而重烘焙一次要 50~70 ms —— 800x40 的地面光是生成像素就 38 ms，
`renderer.prune({})` 还会清掉全部贴图缓存（重烘焙产生新 body id，缓存按 id 存）。

**但拖动只改了位置/旋转，形状一点没变**，根本不需要重烘焙。

**修法**：拆成两条路
- `on_child_transformed()` —— 拖动：只同步 position/rotation + update_aabb + sync
- `on_child_moved()` —— 形状内容变了：仍然完整重烘焙

**实测**：50~70 ms/帧 → **1.891 ms/帧**（约 15 FPS → 约 528 FPS），**32 倍**。

### 移动卡顿（同一个病的第二次）

上一次只给**形状子节点**加了缓存，漏了 `PixelBody2D` 的**内置**形状 ——
而 demo 用的正是内置 `rect_size`，所以一点没改善。

**实测**（内置 800x40 地面）：`get_shape()` 冷 **37.024 ms** → 之后 **0.0005 ms**。

失效改用**输入签名**比较，不靠 setter 手动失效
（5 个属性 + scale 都影响形状，少接一个就是静默 bug）。

### 掉帧其实从未修掉

`_dirty.get(body.id, true)` + `erase()` —— **默认值就是真正的状态，删除毫无意义**，
那个 `else` 分支是死代码，于是每帧都在重建 800x40 的贴图。

**实测**：200 帧一直在动，重建 **200 次** → 修后 **1 次**。
改用 `PixelShape.revision`（谁改了内容谁 +1，读取方只比版本号）。

### 接触冲量回填完全空转

默认配置下 `_packed_manifolds = true` → `manifolds = []` →
回填遍历的是**空数组**，`Contact.impulse` 永远是近似值、`tangent_impulse` 恒为 0。

**修法**：不用求解器内部状态，改用**动量变化**算 —— `J = m_eff · Δv`。
对原生和 GDScript 两条路径都成立，**零 C++ 改动**，顺便解决了偏心撞击高估（忽略转动项）。

### 拖动时形状不跟随

`NOTIFICATION_TRANSFORM_CHANGED` **默认不发**，必须显式 `set_notify_transform(true)`。
（测试是手动调 `notification()` 的，所以断言全过但编辑器里依然拖不动。）

### 编辑器里物体自己动

`@tool` 脚本定义 `_physics_process` **本身就启用它**，
`_ready` 里那句守卫挡不住，守卫必须写在函数体里。

## 修复（正确性）

| 问题 | 后果 |
|---|---|
| `thickness_at` **方向反了** | `thin` 恒等于 4 → `shear_ratio` 与材料厚度无关 → **抗剪强度从未生效** |
| 接触宽度窗口写死 ±24 | 60 和 200 px 宽都算成 49，应力高估 1.2×/4× |
| 投机接触那帧宽度恒为 0 | **冲量最大的一击上 `σ = impulse/0` 失效** |
| `CIRCLE` 从 `-radius` 铺像素 | 与 `RECT`/`TEXTURE` 原点语义不一致 → 碰撞箱与精灵图对不上 |
| 材质 id 越界取模回绕 | `7 % 7 = 0` → 索引 0 全透明 → **像素在画面上直接消失**（物理还在） |
| `make_key` 的 id 截 16 位 | id 超 65535 后 warm 冲量**串号**（fracture 一直在发新 id） |
| 精灵签名有盲区 | 「洞在 (2,2)」与「洞在 (6,6)」签名相同 → 精灵停在旧像素 |
| 多边形 `inset` 切出不连通形状 | 违反「形状必须 4 邻域连通」的不变量 |
| 「0 = 不参与破坏」约定不一致 | 配了强度的材质在**剪切方向永远不破坏**，且不报错 |
| `viewport` 拉伸模式 | 窗口非 16:9 时画面被拉伸，像素变非正方形 |

**「矛能破盾」现在真的成立** ✓：同一形状两种撞击姿态，窄接触应力是宽接触的 **31.5 倍**
（修之前一直卡在 1.0~1.1 倍）。

## 修复（工程）

- **构建产物移出项目树** —— addon 的 `class_name` 与 `src/` 必然重名，住在树里会让编辑器
  报 `Class X hides a global script class` 并**级联到编译失败**。`.gdignore` 挡不住，
  清 `filesystem_cache` 也没用。实测 headless 同样受影响。
- **生成 addon 时去掉 `class_name`** —— addon 内部引用全是路径式，`class_name` 不是必需的。
- **`Unrecognized UID` 刷屏** —— 整体重写 `.tscn` 时丢了 header 里的 `uid=`。
- **CI 空转** —— manual API 检查在 addon 缺席时「跳过并 exit 0」，
  **看起来是绿的**。现在缺席即失败（可显式豁免）。
- **发布闸门** —— `promote.py` 必须显式 `--yes` 才推 `stable`（开发只在 main，发布由人决定）。

## 新增

- **`--verify` 一条命令**：`python tools/build_addon.py --verify` 构建 → 自检 → 自动移出项目树。
  顺序是强制的，固化进命令而不是写文档让人记。
- **`tools/make_release.py`** —— 用 GitHub API 建 Release，正文从仓库发布说明读（两边同源）。
- **`PixelShading`** —— 逐像素着色（边沿压暗 + 顶面提亮 + 色调扰动），烘进贴图、运行时零开销。
  **默认关闭**：实测在成片地面上读起来是噪点而不是质感，像素画要的是干净利落的色块。
- **demo 场景改用形状子节点** —— 形状可在编辑器里单独选中/拖动/改属性，一个刚体可挂多个。
